FlowBusters

FlowBusters is a security research proof of concept that uses AI agents to propose business-logic abuse tests from recorded browser workflows, with backend execution and evidence verification.

“The lock was only painted.”

A short walkthrough of FlowBusters in action.

What It Does

FlowBusters captures UI snapshots and HTTP traffic while you perform legitimate workflows in Chromium through Playwright MCP. AI agents analyze the evidence, build a state map, infer candidate business rules, and propose structured test plans using relevant attack patterns.

The backend validates test plans against the configured scope and recorded evidence, generates and executes supported HTTP probes, and checks the resulting application state against the rule being tested.

Testing can focus on one workflow or combine actions from multiple recorded workflows that share application state. The goal is to identify unsafe outcomes caused by missing prerequisites, inconsistent state checks, or interactions between otherwise legitimate operations.

AI proposes. The backend executes and verifies. A human reviews whether the inferred rule reflects the intended business behavior.

Attack Patterns

Attack patterns guide hypothesis generation. Agents suggest relevant tests from the recorded states and transitions; a pattern is not itself a finding, and not every pattern applies to every assessment.

Skip Step

Attempt a later workflow action without completing a required prerequisite.

Role Swap

Attempt an action using another user or role context, where the required authorized sessions are available.

Data Tamper

Modify identifiers, statuses, or other values that affect workflow state or ownership.

Mass Assignment

Submit fields that the user should not be allowed to control, including fields unavailable in the UI.

Pricing Tamper

Manipulate submitted prices, discounts, or other inputs used to calculate a financial amount.

Double Spend

Attempt to obtain repeated financial value from an operation that should only provide it once.

Replay Attack

Resubmit a previously valid request after it should no longer be accepted.

Forced Browsing

Directly request a resource or endpoint that should be restricted by server-side access checks.

Cross-flow Analysis

Some business-logic flaws appear only when separate workflows interact. FlowBusters can combine actions from selected recordings into a shared state map and propose tests that cross workflow boundaries, while preserving references to the source evidence.

For example, a price adjustment and a refund may each appear valid in isolation. Combined, they may return more money than the customer originally paid.

Test actions remain tied to captured requests and configured scope. An unrecorded UI action can suggest an investigation, but its visibility alone does not supply an executable API request.

Execution & Verification

Before execution, the backend checks the proposed plan against scope, supported request methods and endpoints, valid fields, source evidence, and supported rule checks. Tests require an independent setup so that earlier probes do not contaminate later results.

After execution, the backend checks the execution log, the actual HTTP requests and responses, and before-and-after application state. The final state is checked against the rule being tested. A successful HTTP response alone does not prove a vulnerability.

For a refund test, that can mean checking whether the total amount returned exceeds the original payment.

CONFIRMED

The executed test and verified evidence demonstrate a violation of the tested rule.

NOT REPRODUCED

The executed test did not reproduce the proposed violation. This does not establish that the application is secure.

NEEDS REVIEW

The available evidence or evaluation is inconclusive and requires human investigation.

These are the main assessment outcomes. Unsupported tests, execution errors, and check errors must remain distinguishable from confirmed findings. Business rules inferred by AI, severity, CWE mappings, and remediation suggestions require human review.

🏴‍☠️ A Tall Tale of the FlowShip

It was the year of our Captain, 1719, when a small crew of very serious software engineers sailed aboard the FlowShip and discovered that locks on the web are mostly for show.

The Recorder walked the ship end to end and wrote every request down. The Analyst spread the leather book across the table and drew a map of the ship’s hold: which crates could only be opened by the foreman, which by the captain, which by no one.

“A lock that only the honest obey is not a lock at all. The lock was only painted!”

Quickstart Concept

Start an assessment within the configured scope
→ perform an authorized workflow in Chromium
→ select “Finish recording”
→ AI proposes tests; the backend validates, executes, and verifies
→ review outcomes, evidence, and inferred business rules

For cross-flow analysis, select multiple recorded workflows that share application state.

Important

FlowBusters is an experimental MVP and is not production-ready. Use it only against non-production systems that you own or have explicit permission to test.

Generated probes may produce false positives or invalid assumptions. Findings require human review. HAR files, tokens, scripts, and reports must be treated as sensitive data.
